Why DuckDB (not a vector DB)?
Your queries ("most expensive supplier", "largest invoice amount") are aggregation queries — SQL is perfect for this. You don't need RAG/embeddings unless you have unstructured text (e.g., contract notes). Use DuckDB because:

Columnar, blazing fast for analytics on CSVs
Zero server setup
Can query CSV/parquet files directly


Agent Design (CrewAI)
python# agents.py
from crewai import Agent, Task, Crew
from langchain_openai import ChatOpenAI

# Point to LM Studio
llm = ChatOpenAI(
    base_url="http://localhost:1234/v1",
    api_key="lm-studio",
    model="local-model"
)

# Agent 1: Router - understands intent
router_agent = Agent(
    role="Query Router",
    goal="Determine if query needs SQL analytics or general insight",
    llm=llm
)

# Agent 2: SQL Agent - translates NL to SQL, executes it
sql_agent = Agent(
    role="SQL Analyst",
    goal="Write and execute SQL queries against supplier database",
    tools=[execute_sql_tool, get_schema_tool],
    llm=llm
)

# Agent 3: Insight Agent - interprets results, explains them
insight_agent = Agent(
    role="Procurement Analyst",
    goal="Interpret query results and provide business insights",
    llm=llm
)
Tools (the critical part)
python# tools.py
import duckdb
from crewai.tools import tool

DB_PATH = "supplier_data.duckdb"

@tool("execute_sql")
def execute_sql(query: str) -> str:
    """Execute a SQL query against the supplier database and return results"""
    conn = duckdb.connect(DB_PATH)
    try:
        result = conn.execute(query).fetchdf()
        return result.to_markdown(index=False)
    except Exception as e:
        return f"Error: {str(e)}"

@tool("get_schema")
def get_schema() -> str:
    """Get the database schema to understand available tables and columns"""
    conn = duckdb.connect(DB_PATH)
    return conn.execute("DESCRIBE supplier_catalog").fetchdf().to_markdown()
Data Ingestion
python# ingest.py
import duckdb
import pandas as pd

def ingest_catalog(filepath: str):
    conn = duckdb.connect("supplier_data.duckdb")
    df = pd.read_excel(filepath)  # or read_csv
    
    # Standardize column names
    df.columns = df.columns.str.lower().str.replace(" ", "_")
    
    conn.execute("CREATE TABLE IF NOT EXISTS supplier_catalog AS SELECT * FROM df")
    print(f"Ingested {len(df)} rows")

Example Query Flow
User asks: "Who are the most expensive suppliers for IT services?"

Router → identifies as analytics query → routes to SQL Agent
SQL Agent → generates:

sql   SELECT supplier_name, AVG(unit_price) as avg_price, SUM(total_amount) as total_spend
   FROM supplier_catalog
   WHERE category = 'IT Services'
   GROUP BY supplier_name
   ORDER BY avg_price DESC
   LIMIT 10

SQL Agent → executes query → returns table
Insight Agent → wraps results in natural language explanation

Key Tips
1. Schema injection is critical — always give the SQL agent the table schema in its system prompt so it doesn't hallucinate column names.
2. Use few-shot examples in the SQL agent's prompt for your specific column names (e.g., supplier_name, invoice_amount, order_date).
3. Add a validation step — have the SQL agent validate its query before executing (syntax check via DuckDB's EXPLAIN).
4. For LM Studio, use a model with strong instruction following and coding ability — Mistral-7B-Instruct or Llama-3.1-8B-Instruct work well for SQL generation. For better SQL quality, CodeLlama-13B or DeepSeek-Coder are worth trying.
5. Start simple — you don't need CrewAI's full multi-agent pipeline initially. A single agent with SQL tools + a good system prompt can handle most queries. Add specialization as complexity grows.
